6. **Runner là Node + `react-router-serve`, không phải nginx** (§3, §8): `react-router build` ra `build/client` + `build/server/index.js`; `react-router-serve` là Express (compression + morgan + `express.static` cho `build/client`), đọc `PORT`/`HOST`/`NODE_ENV`, và **khi `PORT` trống thì tự chọn cổng rảnh** (`getAvailablePort(3000)`) — container phải `ENV PORT`. Không có "standalone" kiểu Next: image = `build/` + `node_modules` production (Dockerfile chính chủ dùng `npm ci --omit=dev`; reference có stage `prod-deps` với `bun install --production --linker=hoisted --filter --omit=peer`). Dev: `react-router dev` có `--port`/`--strictPort`, và đọc `server.port` của `vite.config.ts` → **`ports.ts` ghép được y như Vite Template cho dev, và như Next Template cho E2E (`webServer.env.PORT`)**.
7. **Env** (§4): `envDir: "../../"` + `envPrefix: "PUBLIC_"` vẫn áp dụng (là Vite), `import.meta.env.PUBLIC_*` được thay tĩnh vào **cả** bundle server lẫn client; Flavor `vite` của `@monorepo/env` dùng lại được **nguyên xi** cho phần public (reference `src/env.ts` là 1 dòng `createEnv(baseEnvSchema, import.meta.env)`). Điều Flavor `vite` **không** có là block `server` cho secret (session secret, API token) — reference cố ý *không* mở (ADR-0019 §4) và hard-code một secret dev-only kèm cảnh báo. Với repo này, nơi Flavor `next` đã có `server`/`client`, câu hỏi "có mở Flavor thứ ba `@monorepo/env/react-router/*` (t3 `env-core` đã có trong catalog) hay không" là quyết định ADR, ghi ở §13.
8. **i18n** (§5): không có i18n first-party. Hai đường primary: `remix-i18next@8.0.0` (peer `react-router ^8`, middleware-based) hoặc cách reference: **dùng lại Flavor `i18next` (`createI18n`) + `resolveLanguage(request)` (cookie → `Accept-Language`) + `i18n.cloneInstance({ lng })` mỗi request trong `entry.server.tsx` + đọc `<html lang>` lại ở `entry.client.tsx`** để hydration không lệch. Không cần Flavor mới nếu theo reference; nếu muốn locale trên URL như Next thì `prefix(":lang?", …)` + `href("/:lang?/about", { lang })` là API chính chủ.
9. **Auth** (§6): guard = `middleware` trên một `layout()` **pathless** + session `createCookieSessionStorage` trong `~/libs/session.server.ts` (hậu tố `.server` làm build fail nếu lọt client); `throw replace(...)` để short-circuit; **và bắt buộc có `loader` trong route guard** vì server middleware chỉ chạy khi có `.data` request (docs nói rõ). Đây là bản framework-mode của đúng hai hình dạng repo đã có: Vite `ProtectedRoute` (quyết định lúc render — sai cho SSR) và Next `proxy.ts` + `decideSessionRedirect` (pure function — `safeRedirectTo` của Next Template dùng lại được nguyên văn).
10. **Data** (§7): `loader` cho thứ crawler đọc + `meta`; TanStack Query cho sau paint; **một giá trị một nhà**, không `dehydrate`/`HydrationBoundary` (rule `patterns-loader-vs-query` của reference, cùng logic `next-data-fetching.md` của repo này). `QueryClient` phải tạo per-render-tree (`useState(getQueryClient)` trong `Layout` của `root.tsx`), giống `getQueryClient()` của Next Template — `~/libs/query-client.ts` xuất singleton như Vite Template **không dùng được** trên server (TanStack docs: "NEVER DO THIS").
11. **Sentry** (§10): `@sentry/react-router@10.73.0` (cùng dòng 10.73 với `@sentry/nextjs` repo đang dùng), peer `react-router 7.x || ^8.x` + `@react-router/node`. Setup gồm 4 mảnh: vite plugin `sentryReactRouter(config, viteConfig)`, `buildEnd: sentryOnBuildEnd`, `instrument.server.mjs` nạp qua `NODE_OPTIONS='--import …'` (Windows phải set tay), `entry.server.tsx` thay bằng `createSentryHandleRequest`/`createSentryHandleError`. Vite Template không ship Sentry; Template mới ship hay không là câu hỏi mở.

### 2.2 `root.tsx`, hai entry, route module

- `root.tsx` là route bắt buộc, sở hữu `<html>`; export tuỳ chọn `Layout` bọc chung `App`/`ErrorBoundary`/`HydrateFallback` ("so a thrown error swaps the content without remounting the shell" — cách reference viết, `ref:src/root.tsx:56-105`), `links`, `meta`, `loader`, `ErrorBoundary`.
- `react-router reveal` "Generates the `entry.client.tsx` and `entry.server.tsx` files in your `app` directory. When these files are present, React Router will use them instead of the defaults" ([dev CLI](https://reactrouter.com/api/other-api/dev)). Reference custom hoá cả hai (i18n per-request, `isbot`, `streamTimeout`) — `ref:src/entry.server.tsx`, `ref:src/entry.client.tsx`.
- Route module exports ([route-module](https://reactrouter.com/start/framework/route-module)): `default` component nhận `Route.ComponentProps` (`loaderData`, `actionData`, `params`, `matches`); `middleware` / `clientMiddleware`; `loader` — "only called on the server when server rendering or during the build with pre-rendering"; `clientLoader` (+ `clientLoader.hydrate`); `action` / `clientAction`; `ErrorBoundary`; `HydrateFallback`; `headers`; `handle`; `links`; `meta`; `shouldRevalidate` — "In framework mode with SSR, route loaders are automatically revalidated after all navigations and form submissions".
- `.server` modules ([server modules](https://reactrouter.com/api/framework-conventions/server-modules)): "The build will fail if any code in a `.server` file or `.server` directory accidentally ends up in the client module graph." và "Route modules should not be marked as `.server` or `.client`".

### 2.3 `routes.ts`

`route(pattern, file, { id? }, children?)`, `index(file)`, `layout(file, children)` ("nests children without adding URL segments"), `prefix(path, children)` ("does not introduce a new route into the route tree"); `satisfies RouteConfig` ([routing](https://reactrouter.com/start/framework/routing)). fs-routes là opt-in: `flatRoutes()` từ `@react-router/fs-routes`, `rootDirectory` mặc định `app/routes` ([file-route-conventions](https://reactrouter.com/how-to/file-route-conventions)) — reference loại vì "đi ngược văn hóa tường minh của repo" (`ref:docs/adr/0019:44-45`); đề xuất giữ nguyên quyết định đó.

### 2.4 Typegen + `href()`

- "React Router generates types for each route … `+types/<route file>.d.ts` … inside the `.react-router/types/` directory. With `rootDirs` configured, TypeScript imports these generated files as if they were co-located" ([type-safety](https://reactrouter.com/explanation/type-safety)). Types sinh: `LoaderArgs`, `ClientLoaderArgs`, `ActionArgs`, `ClientActionArgs`, `HydrateFallbackProps`, `ComponentProps`, `ErrorBoundaryProps` (+ `MiddlewareFunction`, `MetaArgs`, `LinksFunction` dùng trong reference).
- How-to nói rõ ba bước ([route-module-type-safety](https://reactrouter.com/how-to/route-module-type-safety)): `.gitignore` thêm `.react-router/`; tsconfig `"include": [".react-router/types/**/*"]` + `"rootDirs": [".", "./.react-router/types"]`; script `"typecheck": "react-router typegen && tsc"`. `react-router typegen --watch` tồn tại; `react-router dev` tự sinh.
- `href<Path>(path, ...args)` — "Param values are percent-encoded … Splat (`*`) values are encoded per segment"; ví dụ `href("/:lang?/about", { lang: "en" }) // -> "/en/about"`; sai path/param là type error ([href](https://reactrouter.com/api/utils/href), changelog).

### 2.5 Middleware — stable, và điều kiện chạy

- v8: "Middleware is **stable** … `export const middleware: Route.MiddlewareFunction[]`, `export const clientMiddleware: Route.ClientMiddlewareFunction[]`" ([middleware](https://reactrouter.com/how-to/middleware)). Context: `createContext<T>(defaultValue?)` → "If a `defaultValue` is provided, it is returned when no value is set; otherwise, reading an unset context throws" ([createContext](https://reactrouter.com/api/utils/createContext)); `context.set(userContext, user)` / `context.get(userContext)`.
- Short-circuit bằng `throw redirect(...)`; server middleware phải `return` Response từ `next()`; client middleware không có Response.
- **Ràng buộc quan trọng**: "In a hydrated Framework Mode app, server middleware … does not create new network activity by default … Client-side navigations will only run server middleware if a `.data` request is made to the server for a `action`/`loader`" — docs đề xuất thêm `loader() { return null }` để ép middleware chạy. Reference dùng chính loader đó để trả `context.get(userContext)` (`ref:src/routes/protected.tsx:17-38`).
- Context7 vẫn trả về snippet `unstable_middleware` từ docs **v7.18.2** — đó là bản cũ, không phải hiện trạng v8.

### 2.6 `data()`, `redirect()`, `replace()`, `useFetcher`

`data(value, { status })` mang status mà không serialize thành Response; `throw data(null, { status: 404 })` khi không có gì để render, `return data(null, { status: 404 })` khi component *là* trang 404 (reference giải thích hai chiều, `ref:src/routes/checkup-package.tsx:23-38`, `ref:src/routes/not-found.tsx:5-18`). `replace()` = redirect + `X-Remix-Replace` (`ref:.agents/rules/routing-middleware-guards.md:52-56`; **chưa xác minh** trên trang API riêng của `replace`).

## §3. Build & serve, và cách ghép `ports.env`

- `react-router build` ra `build/client` (assets, `public/` gộp vào) và `build/server/index.js` (`buildDirectory`/`serverBuildFile` mặc định; reference Dockerfile mô tả, `ref:Dockerfile:75-78`). `react-router build` "Sets `process.env.NODE_ENV` to `production`" ([dev CLI](https://reactrouter.com/api/other-api/dev)).
- `react-router dev` flags: `--port`, `--strictPort` ("Exit if specified port is already in use"), `--host`, `--open`, `--mode` ([dev CLI](https://reactrouter.com/api/other-api/dev)). Nó chạy trên Vite, nên `server.port` trong `vite.config.ts` cũng có tác dụng — reference đặt `server: { port: 3001, open: true }` và dev đúng 3001 (`ref:vite.config.ts:44-47`, `ref:AGENTS.md:77`). `server.strictPort: true` qua config: **chưa xác minh** riêng (reference không đặt), nhưng có cờ CLI tương đương.
- `react-router-serve` ([serve](https://reactrouter.com/api/other-api/serve)): "a production-ready but basic Node.js server built with Express"; `PORT=4000 npx react-router-serve build/index.js`; "You can configure the hostname … via `process.env.HOST`"; "Depending on `process.env.NODE_ENV`, the server will boot in development or production mode"; middleware mặc định `compression`, `express.static`, `morgan`; "If you find you want to customize it, you can migrate to the `@react-router/express` adapter". Từ source `cli.ts` ([raw](https://raw.githubusercontent.com/remix-run/react-router/main/packages/react-router-serve/cli.ts)): `parseNumber(process.env.PORT) ?? (await getAvailablePort(3000, process.env.HOST))` — **`PORT` trống → thử 3000 → nếu bận thì cổng 0 (hệ điều hành cấp ngẫu nhiên)**; `express.static(…/assets, { immutable: true, maxAge: "1y" })` + `express.static(build.assetsBuildDirectory)`; `["SIGTERM","SIGINT"].forEach(signal => process.once(signal, () => server?.close(console.error)))`. Không có `--strictPort` — reference ghi nhận đúng rủi ro "a dev server left running would quietly be reused" (`ref:playwright.config.ts:3-9`).
- Custom server: `createRequestHandler` từ `@react-router/express` với `build: () => import("virtual:react-router/server-build")` và `getLoadContext()` trả `new RouterContextProvider()` (template chính chủ `node-custom-server/server/app.ts`); `server.js` đọc `Number.parseInt(process.env.PORT || "3000")` ([raw](https://raw.githubusercontent.com/remix-run/react-router-templates/main/node-custom-server/server.js)).
- **SPA mode `ssr: false`** ([spa](https://reactrouter.com/how-to/spa)): "only disables _runtime server rendering_. React Router will still server render your root route at _build time_ to generate the `index.html`"; "You cannot include a `loader` in any other routes … unless you are pre-rendering those pages"; `clientLoader`/`clientAction` thay thế; deploy `build/client` lên static host với rewrite `/* → /index.html 200`. Với `ssr:false` còn "cannot include `actions` or `headers` functions" ([pre-rendering](https://reactrouter.com/how-to/pre-rendering)). → SPA mode **trùng vai** với `_template_vite` + nginx; lý do tồn tại của Template thứ ba là SSR, nên **`ssr: true`** (reference quyết định giống, `ref:docs/adr/0019:27-29`: "hạ từ SSR xuống SSG dễ hơn chiều ngược lại").
- **Prerender cùng SSR**: "When pre-rendering with `ssr:true`, you're indicating you will still have a runtime server but you are choosing to pre-render certain paths"; emit `[url].html` + `[url].data` trong `build/client`; loader chạy lúc build qua `new Request()`. Reference: `prerender: ["/about"]`, **không** `prerender: true` vì nó sẽ emit `build/client/index.html` cho `/` và `express.static` đứng **trước** request handler → `/` lặng lẽ hết SSR (`ref:react-router.config.ts:13-24`); hệ quả quan sát được: `/about` → `301` sang `/about/` (serve-static), `about.data` phục vụ off disk với `accept-ranges: bytes` (`ref:e2e/prerender.e2e.ts:75-108`).

**Ghép vào convention `ports.env` / `ports.ts` của repo này** (`apps/_template_vite/ports.ts:40-52`, `apps/_template_next/package.json:8-10`):

| Cổng | Vite Template | Next Template | Framework Template (đề xuất) |
|---|---|---|---|
| dev | `vite.config.ts` `server.port: DEV_PORT` từ `./ports.ts` | `dotenv -e ./ports.env -- next dev` (Next đọc `PORT`) | `vite.config.ts` `server.port: DEV_PORT` (+ `strictPort`) từ `./ports.ts` — `react-router dev` là Vite |
| E2E | `vite.config.ts` `preview.port: E2E_PORT` | `webServer.env.PORT: String(E2E_PORT)` | `webServer.env.PORT: String(E2E_PORT)` → `react-router-serve` đọc `PORT` — **giống Next**, vì không có `preview` |

Reference hard-code `3001`/`3101` trong hai file (`ref:vite.config.ts:45`, `ref:playwright.config.ts:8`) vì reference **không có** `ports.env`; repo này thay bằng `ports.ts` byte-identical với hai Template kia (comment của `ports.ts` đã nói "Both Runtimes import this one — Vite as `preview.port`, Next as `webServer.env.PORT`", chỉ cần thêm vế thứ ba). Script `start` là `react-router-serve ./build/server/index.js`; **không** cần `dotenv-cli` cho dev/build (Vite tự đọc root `.env` qua `envDir`) — chỉ cần nếu muốn `bun run start` tự lấy `PORT` từ `ports.env` khi chạy tay; Playwright ép qua `env` nên không bắt buộc.

## §4. Env — Flavor nào

- Vite docs ([env-and-mode](https://vite.dev/guide/env-and-mode)): `import.meta.env` "statically replaced at build time"; prefix mặc định `VITE_`, đổi bằng `envPrefix`; `envDir` quyết định thư mục `.env`; **"`VITE_*` variables should _not_ contain sensitive information such as API keys"**; `import.meta.env.SSR` là boolean "whether the app is running in the server" và trong SSR guide: "`if (import.meta.env.SSR) { … }` … statically replaced during build" ([ssr](https://vite.dev/guide/ssr)).
- Framework mode = Vite, nên `envDir: "../../"` + `envPrefix: "PUBLIC_"` của `apps/_template_vite/vite.config.ts:22-23` áp dụng nguyên xi; reference copy đúng hai dòng (`ref:vite.config.ts:26-30`) và `src/env.ts` là **một dòng** `createEnv(baseEnvSchema, import.meta.env)` với Flavor vite (`ref:src/env.ts:1-8`). Reference khẳng định "`react-router build` bakes the same PUBLIC_* values into the SERVER bundle as literals, so the runner needs no PUBLIC_* at boot" (`ref:Dockerfile:52-54`) — nhất quán với Vite docs "statically replaced", nhưng phần "trong bundle server" là kết quả spike của reference, **chưa tự xác minh** ở đây.
- Dockerfile validate bằng `bun --env-file=/app/.env -e "import './src/env.ts';"` — chạy được vì "`import.meta.env` is Vite's baked record in the browser and an alias of `process.env` under Bun" (`apps/_template_vite/Dockerfile:52-56`; reference lặp lại `ref:Dockerfile:60-73`). Hình dạng này giữ nguyên.
- **Secret server-side** — chỗ Flavor `vite` thiếu: framework mode có `loader`/`action`/`.server.ts` chạy trong Node, đọc được `process.env` lúc runtime (docs server-modules dùng `process.env.JWT_SECRET` làm ví dụ). Nhưng Biome của repo này cấm `process.env` dưới `apps/**` trừ `**/env.ts` và `**/*.config.*` (`biome.json:106-124`, `:147-155`). Reference chọn **không mở**: "ADR-0019 §4 deliberately did not open a server-side runtime env schema … Opening that door is a decision of its own, with an ADR, a Dockerfile `ENV` and a `docs/ops/` note behind it" và hard-code `DEV_ONLY_SESSION_SECRET` kèm cảnh báo phải thay trước khi deploy (`ref:src/libs/session.server.ts:14-30`).
- Repo này khác reference ở một chỗ quyết định: Flavor `next` **đã** có block `server` (t3-env, `packages/env/src/next/create-env.ts:52-56`) và `.env.example` đã có nhóm "Server-only variables carry NO prefix" (`.env.example:63-88`, ví dụ `MCP_WEATHER_OPENWEATHERMAP_API_KEY`). Ba đường cho Template thứ ba:
  1. **Giữ Flavor `vite` nguyên xi** (như reference) — 0 code mới, secret không có nhà, session secret là hằng dev-only.
  2. **Flavor thứ ba `@monorepo/env/react-router/*`**: `createEnv({ server, client })` trên `@t3-oss/env-core` (đã ở catalog default: `"@t3-oss/env-core": "0.13.11"`, `package.json:60` — hiện không package nào dùng), `client` = `baseEnvSchema` `PUBLIC_*` đọc từ `import.meta.env`, `server` đọc `process.env` **chỉ trong `env.ts`** (được Biome miễn). Hợp ADR-0003 ("mỗi Flavor giữ tiền tố chuẩn của Runtime") — Runtime này tiền tố `PUBLIC_` như Vite, nhưng có thêm nửa server như Next. Điểm cần cẩn thận: `env.ts` được import từ cả client lẫn server graph; t3-env `isServer` quyết định bằng `typeof window`, và phần `server` phải "vanish" trên client đúng như Flavor next (`packages/env/README.md:155-158`).
  3. Đọc `process.env` trong một `*.server.ts` và mở rộng override Biome cho `**/*.server.ts` — rẻ nhất, nhưng phá "một file schema" (`CLAUDE.md` §2 Env note: "There is no separate `env-schema.ts`").
  → Câu hỏi ADR (§13). Note này không chọn thay.
- Tên key: `.env.example` là **một file cho cả workspace**; app thứ ba với `PUBLIC_` sẽ đọc chung `PUBLIC_BASE_DOMAIN=http://localhost:3000` của Vite Template (`.env.example:22-24`) — theo quy ước `packages/env/README.md:63-98` "Chỉ **một** app đọc → mang tên app". Template là Template nên có thể dùng key trần như hai Template kia (Next Template cũng dùng `NEXT_PUBLIC_BASE_DOMAIN=…:3001`), nhưng `BASE_DOMAIN` của một app SSR trên 3005 mà build bằng `localhost:3000` là sai về origin canonical (reference dùng `url.origin` từ request cho canonical thay vì env, `ref:src/routes/checkup-package.tsx:42-54`). Ghi §13.
- `turbo.json` root `globalEnv: ["PUBLIC_*", "NEXT_PUBLIC_*"]` (`turbo.json:42`) — đã cover.

## §5. i18n — locale ở đâu, Flavor nào

- React Router **không có i18n first-party** (không có trang docs; reference research 29/08 cũng kết luận vậy). Hai đường primary:
- **`remix-i18next@8.0.0`** (README [raw](https://raw.githubusercontent.com/sergiodxa/remix-i18next/main/README.md)): peer `react-router ^8.0.0`, `i18next ^24||^25||^26` (repo có `i18next ^26.4.1`, `package.json:67`); `time.modified` 2026-06-25. Mô hình **middleware**: `const [i18nextMiddleware, getLocale, getInstance] = createI18nextMiddleware({ detection: { supportedLanguages, fallbackLanguage }, i18next: { resources }, plugins: [initReactI18next] })`; `root.tsx` `export const middleware = [i18nextMiddleware]` + `loader` trả `getLocale(context)` + `useEffect(() => { if (i18n.language !== locale) i18n.changeLanguage(locale) })`; `entry.server.tsx` `<I18nextProvider i18n={getInstance(routerContext)}>`; `entry.client.tsx` detection `order: ["htmlTag"]`. "For React Router SPA Mode, use `react-i18next` directly." Cộng thêm một dependency, và một `useEffect` đồng bộ ngôn ngữ.
- **Cách reference — không thêm dependency**, dùng lại Flavor `i18next` của `@monorepo/i18n` (`createI18n`, `packages/i18n/src/i18next/create-i18n.ts:41-70`):
  - `~/utils/resolve-language.ts` (`ref`): server chọn ngôn ngữ theo **cookie → `Accept-Language` (sắp theo `q`)**, cả hai đi qua registry `languages`, bỏ region như `load: "languageOnly"` (`ref:src/utils/resolve-language.ts:6-29`, `:58-98`). Đây là phần **không phụ thuộc thư viện** — ứng viên tự nhiên cho một subpath ngoài Flavor (`@monorepo/i18n/resolve-language`?) hoặc Flavor `./react-router/*`.
  - `entry.server.tsx`: "Calling `i18n.changeLanguage()` here would … be a race … `cloneInstance` is i18next's answer — the clone shares the loaded resources … but owns its own language" → `i18n.cloneInstance({ lng: resolveLanguage(request), initAsync: false })` bọc `<I18nextProvider>` (`ref:src/entry.server.tsx:35-52`). i18next docs: `cloneInstance` "Creates a clone of the current instance. Shares store, plugins and initial configuration" ([i18next API](https://www.i18next.com/overview/api)); react-i18next SSR: "use the I18nextProvider to inject the i18next instance for example bound to the http i18n instance on the request object" ([react-i18next SSR](https://react.i18next.com/latest/ssr)).
  - `meta()` chạy ngoài React tree → `i18n.getFixedT(loaderData.language)` ("Returns a `t` function that defaults to given language") (`ref:src/root.tsx:38-54`).
  - `entry.client.tsx`: đọc `document.documentElement.lang` mà server đã ghi, `changeLanguage` về đúng nó **trước** `hydrateRoot` để không hydration mismatch; giữ lại cookie của visitor vì trang prerender có `lang` của build (`ref:src/entry.client.tsx:11-69`).
  - `LanguageDetector` của browser chạy trong `createI18n` trên Node: reference đã chạy SSR thật (E2E `shell.e2e.ts` pin `Accept-Language`) — coi như đã chứng minh ở reference, **chưa xác minh riêng** trong repo này.
- **Locale trên URL** (như `[locale]` của Next Template): API chính chủ là `prefix(":lang?", […])` trong `routes.ts` + `href("/:lang?/about", { lang })` ([href](https://reactrouter.com/api/utils/href) ví dụ đúng shape này). Reference chọn cookie + header (không URL) — hai Template SSR của repo này sẽ **khác nhau** về nơi locale sống nếu giữ như reference; ADR-0002 đã dự liệu "sau này React Router framework" nhưng không chốt URL hay cookie. Ghi §13.
- Catalogue ICU + `catalogue-invariants.test.ts` không đổi; namespace message mới (`templateReactRouter.*` ở reference) là thêm key, không đổi cơ chế.

## §6. Auth guard — middleware + cookie session

Nguồn: [middleware](https://reactrouter.com/how-to/middleware), [sessions-and-cookies](https://reactrouter.com/explanation/sessions-and-cookies), reference `session.server.ts`, `session-guard.server.ts`, `routes/protected.tsx`, ADR-0020.

- Sessions docs: `createCookieSessionStorage<SessionData, SessionFlashData>({ cookie: { name, domain?, httpOnly, maxAge, path, sameSite, secrets, secure, expires? } })` → `getSession(request.headers.get("Cookie"))`, `commitSession`, `destroySession`; "We recommend setting up your session storage object in `app/sessions.server.ts`". Reference: `httpOnly: true`, `sameSite: "lax"`, `path: "/"`, `maxAge: 8h`, `secrets: [DEV_ONLY_SESSION_SECRET]`, và `secure` **quyết định per request** (fail-closed: chỉ bỏ `Secure` khi loopback http) vì `react-router-serve` "never calls `app.set("trust proxy")`" và `PUBLIC_APP_ENV` là build-time (`ref:src/libs/session.server.ts:58-101`). Next Template đặt `secure: env.NEXT_PUBLIC_APP_ENV !== "local"` (`apps/_template_next/src/features/auth/actions/sign-in.ts:38-41`) — hai cách, nên chọn một khi viết spec.

## §7. Data — loader vs TanStack Query

- Route-module docs: `loader` "only called on the server when server rendering or during the build with pre-rendering"; `clientLoader` "provide data … in addition to, or in place of, route loaders", `clientLoader.hydrate` để tham gia hydration, kèm `HydrateFallback`; `shouldRevalidate` opt-out revalidate ([route-module](https://reactrouter.com/start/framework/route-module)).
- TanStack SSR guide ([ssr](https://tanstack.com/query/latest/docs/framework/react/guides/ssr)): "NEVER DO THIS: `const queryClient = new QueryClient()` … Creating the queryClient at the file root level makes the cache shared between all requests … leaks any sensitive data" → `React.useState(() => new QueryClient(...))`; mẫu prefetch + `dehydrate` + `<HydrationBoundary>`. Ví dụ `examples/react/react-router` (loader `queryClient.ensureQueryData(...)` rồi `useQuery({ …, initialData })`) **là data mode với `react-router-dom`** (import từ `react-router-dom`, `LoaderFunctionArgs`) — mẫu cộng đồng/data-mode, không phải hướng dẫn framework-mode; reference research 29/08 cũng ghi "docs chính thức không có hướng dẫn first-party nào về việc trộn loaders với React Query" (`ref:docs/research/react-router-v7-framework-mode-template.md:81`).
- Quyết định reference (ADR-0019 §7, rule `patterns-loader-vs-query`): loader = SEO/first-paint + `meta`; Query = sau paint; **không mirror** (không `dehydrate`); `QueryClient` per tree — `useState(getQueryClient)` trong `Layout` của `root.tsx` (`ref:src/root.tsx:76-85`), `~/libs/query-client.ts` xuất **factory** `getQueryClient()` chứ không singleton như `apps/_template_vite/src/libs/query-client.ts:10`. Đây chính là hình dạng `apps/_template_next/src/libs/query-client.ts` đã có (`CLAUDE.md` §1: "`getQueryClient()`, not a module singleton"). Rule `next-data-fetching.md` của repo này nói cùng một ranh giới ("One value, one home — never both") — nên rule `patterns-loader-vs-query` khi port cần **liên kết** với nó thay vì lặp.
- Hệ quả lên `~/libs/http-client.ts`: "nothing here may touch `window`" vì loader import nó trong Node (`ref:src/libs/http-client.ts:11-20`); `getAuthToken` không còn đọc store — với cookie session, service gọi từ loader phải nhận token/cookie từ `request` (reference chưa có backend nên để trống; **chưa xác minh** hình dạng cuối); `onUnauthorized` không thể `queryClient.clear()` một singleton.

## §8. Docker — Node runner, không standalone

Mỗi dòng có lý do ghi tại chỗ — port sang `@monorepo/*` là đổi tên.

### 12.4 Những chỗ framework mode **không thể** khớp convention hiện có (phải ghi thành rule, không "sửa cho giống")

1. **Không có `~/pages/`**: top layer là `~/routes.ts` + `~/routes/<name>.tsx` (route module = "the thin wrapper the SPA's `~/pages/<feat>-page.tsx` was"); thêm ba file framework ở gốc `src/`: `root.tsx`, `entry.client.tsx`, `entry.server.tsx` (Vite Template có `index.tsx`; Next có `src/app/[locale]/layout.tsx`).
2. **Không có `~/constants/routes.ts`**: `href()` typed thay `ROUTES` (rule `routing-typed-href`); `routing-constants.md` hiện nói "Both Runtimes keep this table" — thành "hai trong ba".
3. **Hậu tố `.server.ts`** là convention mới (`~/libs/session.server.ts`, `~/features/auth/middleware/session-guard.server.ts`, `verify-credentials.server.ts`) — cả hai Template kia không có; và route module **không được** mang hậu tố đó.
4. **Slice `auth` có `middleware/`** thay `provider/` (Vite) / `guard/` + `actions/` (Next); sign-in là `action` trong route module (`routes/sign-in.tsx`), không phải Server Action file riêng, không phải mutation hook.
5. **Không `~/stores/use-auth-store.ts`** (như Next); `~/libs/http-client.ts` không được đụng `window`.
6. **`typecheck` = hai lệnh** (typegen trước `tsc`), `.react-router/` sinh ra, `rootDirs` trong tsconfig — giống `next typegen && tsc` của Next Template về tinh thần (`apps/_template_next/package.json:11`).
7. **Output `build/`** (client + server) thay `dist/` (Vite) / `.next/standalone` (Next) → `turbo.json` app-level outputs khác.
8. **Vitest hoán plugin** (`reactRouter()` ↔ `react()`) — chỗ duy nhất hai plugin loại trừ nhau.
9. **`QueryClient` là factory** (`getQueryClient()` + `useState` trong `root.tsx`), không singleton — giống Next, khác Vite; `query-client.ts` của Vite Template không copy được.
10. **`prerender` là literal** trong config (typegen chưa chạy) — ngoại lệ duy nhất của quy tắc "không literal path".
11. **Trang prerender trả 301 thêm `/`** và `about.data` off disk — hành vi của `serve-static`, cần E2E biết.
12. **Runner Node + `PORT` bắt buộc trong image**, không nginx, không `nginx.conf` — Next Template đã mở đường (Bun builder → `node:24-alpine`), nhưng đây không có `standalone`.
13. **Cookie `secure` per-request** (reference) vs build-time `env` (Next) — hai cách trong repo nếu port nguyên.
14. **E2E phải sign-in thật** (HttpOnly) — `e2e/support/auth-session.ts` không seed `localStorage` được.
